# 老地图图幅编目与地名对照台

面向古地图整理者和地方志研究者，将老地图按图幅编目，登记年代、比例尺、投影和扫描件，并建立古今地名对照及沿革线索。应用为纯前端单页程序，所有资料保存在浏览器本地。

## Docker 一键启动

```bash
cp .env.example .env && docker compose up -d --build
```

服务默认映射到宿主端口 `21805`。停止服务可执行：

```bash
docker compose down
```

## 数据存储说明

应用使用 IndexedDB 持久化数据，Dexie 数据库名为 `gboldmap-db`。数据库包含 `sheets`、`scans`、`placePairs`、`histories`、`revisions`、`revisionStaging` 六个对象仓库：

- `version(1)` 建立首版索引结构，并在首次创建数据库时写入图幅、扫描件、地名对照和沿革种子数据。
- `version(2)` 保持现有索引并对已有图幅执行 `schemaRev = 2` 的回填迁移，用于演示后续结构升级路径。
- `version(3)` 为图幅增加 `version`（图幅版本）索引，迁移时把既有图幅回填为版本 1；新增 `revisions`（已应用修订批次留档）与 `revisionStaging`（待确认区暂存）两个仓库。

刷新或关闭页面不会丢失新增记录；浏览器站点数据被清除时会重新触发首次种子数据写入。

## 离线修订对账

地方志馆常把兄弟馆的离线编目修订表带回本机。在「离线修订对账」页（`/revisions`）把修订表纯文本贴进待确认区后，系统按**图幅号 + 图幅版本**与本地编目对账，只有一个批次里的图幅、扫描件、四至关系都能落到同一版本时，才允许整批一起写入：

- **重号图幅 / 版本冲突**：同图幅号同版本本地已存在，或批次版本不高于本地版本，直接追加会留下重号图幅，需处理后再提交。
- **扫描件挂旧图**：批次带了某图幅号的扫描件时，写入会整幅替换为新版本并替换扫描件集合，防止扫描件继续挂在已被替换的旧图上。
- **邻接指向旧图**：四至可写 `邻接图号@版本`，指向版本与本批/本地确认版本不一致即报版本冲突；缺编图号报缺口。
- **失败可重试**：整批写入是单个 IndexedDB 事务，任何一步失败全部回滚；待确认区文本单独持久化，仍保留在本机，处理完缺口或版本冲突后可再次提交。
- **同批幂等**：批次按归一化文本的 SHA-256 摘要留档，同一批资料再次导入直接沿用首次结果，不重复写库。

写入成功后图幅列表、图幅详情与邻接页统一 `reload`，读到的都是已确认版本。

修订表文本按空行分块，块首行标明类型，块内每行 `字段：值`：

```text
图幅：北平-乙-3 版本：2
题名：东单至朝阳门内街巷图（实测修订）
年代：1935
比例尺：1:5000
投影：三角测量 · 平面图
图幅尺寸：58 × 46 厘米
图组：京师实测图
状态：待核

扫描件：北平-乙-3 版本：2
文件名：北平乙3_实测修订_600dpi.tif
分辨率：600
色彩模式：彩色
分块数：6
图像质量：清晰
存放位置：数字地图库 A-1935-09
主用件：是

四至：北平-乙-3 版本：2
西：北平-甲-3@1
南：北平-丙-5@1
```

## 核心功能与路由表

| 路由 | 核心功能 |
| --- | --- |
| `/sheets` | 按年代、比例尺和状态筛选图幅，内联新建图幅，查看版本、扫描件数、地名数与邻接缺编提示 |
| `/sheets/:id` | 查看编制摘要、确认版本、扫描件条目、主用件切换、图内地名检索及 JSON 导出 |
| `/revisions` | 粘贴离线修订表，按图幅号与版本对账，处理缺口/版本冲突后整批原子写入 |
| `/places` | 古今地名双栏对照，按类型和确定度筛选，对古名、今名、异写及图上方位反向查询并高亮 |
| `/places/:id/history` | 按年代排列沿革时间线，新增初置、改名、迁治或废置记录 |
| `/sheets/:id/neighbors` | 按四至排列邻接图幅，显示主用扫描件、缺编提示与拼合预览 |
| `/`、未匹配路径 | 自动跳转到 `/sheets` |
