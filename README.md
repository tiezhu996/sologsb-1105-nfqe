# 老地图图幅编目与地名对照台

面向古地图整理者和地方志研究者，将老地图按图幅编目，登记年代、比例尺、投影和扫描件，并建立古今地名对照及沿革线索。应用为纯前端单页程序，所有资料保存在浏览器本地。

## Docker 一键启动

```bash
cp .env.example .env && docker compose up -d --build
```

服务默认映射到宿主端口 `21805`。停止服务可执行：

```bash
docker compose down
```

## 数据存储说明

应用使用 IndexedDB 持久化数据，Dexie 数据库名为 `gboldmap-db`。数据库包含 `sheets`、`scans`、`placePairs`、`histories`、`appliedRevisions` 五个对象仓库：

- `version(1)` 建立首版索引结构，并在首次创建数据库时写入图幅、扫描件、地名对照和沿革种子数据。
- `version(2)` 保持现有索引并对已有图幅执行 `schemaRev = 2` 的回填迁移，用于演示后续结构升级路径。
- `version(3)` 为图幅增加 `version`（图幅版本）索引，并新增 `appliedRevisions` 仓库记录已落位的离线修订批次（批次号、内容指纹与落位时间）；已有图幅自动回填为版本 1。

刷新或关闭页面不会丢失新增记录；浏览器站点数据被清除时会重新触发首次种子数据写入。

## 离线修订对账

兄弟馆带回的离线编目修订表在「离线修订对账台」（`/revisions`）处理：

1. 整理员把修订表文本贴入待确认区，文本按 `【图幅】`、`【扫描件】`、`【四至】` 三段解析，以「批次号」标识批次；待确认内容暂存在本机（localStorage），刷新或应用失败都不丢失。
2. 点「按图幅号与版本对账」后只生成对账报告、不写入：重号图幅必须以更高版本替换；扫描件必须挂到本批次同版本图幅；四至两端的图幅版本必须对得上，邻图不在批次内须以「图号@版本」标明。馆藏缺口、同版重号、旧版回退、扫描件挂旧图等问题全部列为阻断项，「确认写入」按钮在有阻断项时不可用。
3. 确认后整批原子写入单个 IndexedDB 事务：图幅沿用原 id 升版（地名对照与沿革不丢）、旧版扫描件整组撤下、四至按批次重新落位并对批次内邻接自动补对向镜像；任一步失败整批回滚，可修改后重试。
4. 同一批资料（按规范化内容指纹判定）再次导入时沿用上一次结果，只提示首次落位时间，不重复写入。
5. 写入完成后，图幅列表、图幅详情和邻接拼合预览读到的都是已确认版本；版本号在三处页面以 `vN` 标记展示。

## 核心功能与路由表

| 路由 | 核心功能 |
| --- | --- |
| `/sheets` | 按年代、比例尺和状态筛选图幅，内联新建图幅，查看扫描件数、地名数与邻接缺编提示 |
| `/sheets/:id` | 查看编制摘要、扫描件条目、主用件切换、图内地名检索及 JSON 导出 |
| `/places` | 古今地名双栏对照，按类型和确定度筛选，对古名、今名、异写及图上方位反向查询并高亮 |
| `/places/:id/history` | 按年代排列沿革时间线，新增初置、改名、迁治或废置记录 |
| `/sheets/:id/neighbors` | 按四至排列邻接图幅，显示主用扫描件、缺编提示与拼合预览 |
| `/revisions` | 离线修订表待确认区，按图幅号与图幅版本对账，同版本整批原子写入 |
| `/`、未匹配路径 | 自动跳转到 `/sheets` |
